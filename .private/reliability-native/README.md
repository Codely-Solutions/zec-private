# Wallet reliability SDK probes

Owner and consumer: the wallet-reliability development session. Retire this opt-in source set after its final native checks and evidence preservation. It is absent from ordinary builds and has no activity or manifest entry.

Apply `include.gradle` to the existing app instrumentation build. Run class `co.electriccoin.zcash.app.reliability.ReliabilitySdkProbe`. The two `*Locally` methods only describe public UFVK components and derive an address. The two network methods require instrumentation argument `runTorBootstrap=true`; optional `lightwalletHost` and `lightwalletPort` select the TLS lightwalletd endpoint (default `zec.rocks:443`). The public SDK factory receives `isTorEnabled=true` before any network access; exchange rates are disabled. Public bulk block downloads retain the SDK's normal transport.

Each network method uses the target process's UID-compatible context wrapped with a unique cache root, a unique alias and prefixed preferences. All SDK file paths resolve inside that owned root; the default app wallet alias is never used. It never opens the target app's wallet or an activity. `finally` closes the synchronizer, calls public `SlipstreamSynchronizer.eraseAlias` to await shutdown, then removes only the verified owned root and preferences. Each stage is bounded to 90 seconds, the body to 210 seconds, cleanup to 60 seconds, and the JUnit method to 300 seconds. A failed cleanup requires inspection of the target package's `cache/reliability_*` roots before retiring the session.

`NativePublicViewingKeys` copies the feature's public librustzcash fixtures. Its Orchard-only variant removes Sapling from the public no-transparent vector and re-encodes ZIP 316 using the retired parser's F4Jumble/Bech32m algorithm at source revision `5b9e1d7c9`; no seed is retained. The independent full vector is from [Zcash's public unified viewing key vectors](https://github.com/zcash/zcash-test-vectors/blob/master/test-vectors/json/unified_full_viewing_keys.json), the first entry containing all three known components. A local framing check established different component bytes from the hardware-shaped vector. No viewing key is printed by these probes.

The keyless probe tests the candidate public route `SlipstreamSynchronizer.new(setup=null, ExistingWallet)` followed by UFVK import and reopen. Its availability is unproven until native execution. The shared-account probe uses view-only and hardware spending-purpose metadata with public viewing keys and historical birthday inputs; it does not create a software seed, complete a historical scan, spend, or establish hardware interoperability.

Source references for SDK 6.0.0:

- [WalletCoordinator](https://github.com/zodl-inc/zodl-android-wallet-sdk/blob/v6.0.0/sdk-incubator-lib/src/main/java/cash/z/ecc/android/sdk/WalletCoordinator.kt) requires a seed-bearing `PersistableWallet` and constructs `AccountCreateSetup`.
- [SlipstreamSynchronizer](https://github.com/zodl-inc/zodl-android-wallet-sdk/blob/v6.0.0/slipstream-lib/src/main/java/com/zodl/slipstream/SlipstreamSynchronizer.kt) exposes the nullable-setup factory and UFVK import. New/Restore require a seed; Existing permits null. Import awaits preparation before stopping/importing/restarting the engine.
- [InstanceGuard](https://github.com/zodl-inc/zodl-android-wallet-sdk/blob/v6.0.0/slipstream-lib/src/main/java/com/zodl/slipstream/internal/InstanceGuard.kt) makes reopen await the preceding asynchronous close.
- [JNI session startup](https://github.com/zodl-inc/zodl-android-wallet-sdk/blob/v6.0.0/backend-lib/src/main/rust/slipstream/mod.rs) documents keyless startup as requiring an existing account. The empty-database probe distinguishes that expectation from the behavior of the public Kotlin route.
